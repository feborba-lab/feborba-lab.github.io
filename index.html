Do discovery ao CRM configurado

Numa implantação, a reunião de discovery vira horas de configuração. Estou construindo um fluxo no n8n que lê a transcrição da reunião, pede a uma IA o blueprint do CRM (funis, etapas, campos e automações) e só aceita o que tiver prova na própria conversa. A IA propõe, o código confere e o consultor aprova.

Regras antes do prompt

  • Todo item precisa citar um trecho literal da reunião. Sem trecho, não entra.
  • O que a reunião não deixou claro vira pergunta para o cliente, não chute.
  • A resposta da IA tem formato fixo, definido por um JSON Schema.
  • Nada é criado no CRM sem a aprovação de uma pessoa.
  • Só transcrições fictícias ou autorizadas. Nunca dados de cliente.

Um trecho real

// validador.js · nó Code do n8n
for (const o of origem) {
  const trecho = normalizar(o.trecho);
  if (trecho.length < 8)
    erros.push(M.trechoCurto(o.item));
  else if (!texto.includes(trecho))
    erros.push(M.trechoInventado(o.item, o.trecho));
}

Trecho que não está na reunião é sinal de invenção: o item é barrado e volta para a IA corrigir.
